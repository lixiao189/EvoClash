# 待办与排期

按依赖排序，后一项通常要等前一项的结果。日期是计划，不是承诺；完成一项就把它删掉，改动写进对应的 PR。

## 平衡与测试

数值迭代的方法见 `design-targets.md`：策划提案 → 审批 → 实现 → 200 局无头对局 → 逐条消融 → 只保留有用的规则。

| 排期 | 事项 | 内容 | 依赖 |
|---|---|---|---|
| 11 月第 1 周 | 校准设计目标 | 按第三轮实测放宽区间：#15 单把武器击杀占比（轨道炮是终极武器，真人还会打不中），#34 非玩家致死占比，#4 单条命时长。只改 `design-targets.md`，单独审批 | 无 |
| 11 月第 2 周 | 真人统计导出 | 从对局日志回放出真人的反应时间、命中率、撤退与搜刮习惯，以及 #6、#32 这类「真人」指标。顺带统计线上已有多少局含真人 | 无 |
| 11 月第 3 周 | 第四轮规则 | 针对校准后仍出界的硬指标，目前是 #34 野怪致死偏高、#2 每分钟玩家击杀偏少 | 校准设计目标 |
| 真人数据够用后 | 用真人统计校准 bot | 调 bot 参数贴合真人统计（反应、误差、撤退阈值、搜刮时长），保持确定性，回放不受影响 | 真人统计导出 |
| 待定 | 模仿学习训练 bot 决策 | 只学「打 / 躲 / 撤 / 搜刮」和目标选择，瞄准走位仍用脚本加真人误差；小网络在服务端推理。只有含真人的对局达到几百局，并且参数校准后 bot 仍明显不像真人时才做 | 用真人统计校准 bot |

不做：端到端模型（成本高，对测平衡回报小）；用强化学习训练测试用 bot（会学出最优解而不是真人打法，只适合用来找漏洞）。
